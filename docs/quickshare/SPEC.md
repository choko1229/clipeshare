# Clipshare Quick 仕様書（確定版 / 2026-11-20）

> 出典: ユーザー（choko1229）との質疑応答で確定した内容。UIは同ディレクトリの `design/` と、デザインキャンバス https://claude.ai/artifact/79AJ4vKmEg1c8MffHqwYLG を参照（キャンバスが正、`design/` は取り込み時点のスナップショット）。

## 1. 目的
VRChat で写真を撮ると自動で Clipshare.link のクイック共有へアップロードされ、共有URLがクリップボードに入る Windows ツール「**Clipshare Quick**」を作る。エクスプローラーで画像・動画を右クリックしてもURLを発行できる。SteamVR 内で通知表示と最小限の操作ができる。Clipshare ユーザー全員向けに一般公開する。

構成: ① Windows クライアント（Rust, リポジトリ `clipshare-qick`）② Clipshare（Next.js / Prisma / NextAuth, リポジトリ `clipeshare`）③ VRChat（写真の出力元）④ SteamVR（通知とパネル）。**実装順は Clipshare 側が先。**

## 2. 確定仕様
| 項目 | 確定内容 |
|---|---|
| クリップボードURL | 共有ページ `/q/{id}`（OGP を追加） |
| 保存期間 | 現行の24時間のまま |
| バナー | **API 経由のみ**適用。トークンあり=バナーなし、匿名=バナーあり。Web 経由の挙動は不変 |
| 画質 | 原寸 / 縮小を選択。縮小=長辺2000pxのWebP（現行と同じ）。原寸=高画質で再エンコード、埋め込み情報（EXIF等）を除去 |
| サイズ上限 | 画像 20MB→50MB。ツール用はレベル別設定（AccountLevel）、`0`=無制限。初期値は現行ログイン上限を引き継ぐ |
| 匿名利用 | 可。バナーあり、1日5件 |
| ファイル種別 | 画像と動画（mp4/mov/webm 等）。動画は現行の変換処理をそのまま使う |
| 撮影時の動作 | 常に自動アップロード（初回起動で同意、既定ON） |
| 複数選択（右クリック） | 全ファイルをアップロードし URL を改行区切りでコピー |
| サイズ超過 | 画像は自動で長辺2000pxに縮小して再送。動画は縮小不可のためエラー表示 |
| 1日上限到達 | 通知して停止、翌日再開。停止中に撮った写真は送らない。数え方は現行Clipshareに合わせる（コードで確認して再利用） |
| オフライン/障害 | 自動再試行、ダメなら失敗として履歴に残す。手動再試行も可 |
| 初回起動時の過去写真 | 無視。起動後に撮った写真だけ送る |
| 履歴 | 直近50件。期限切れは「期限切れ」表示で残す。URL再コピー・削除 |
| 認証 | ブラウザ認可（ループバック+PKCE）。端末ごとのトークン、失効するまで有効、端末数無制限 |
| トークン保管 | Windows 資格情報マネージャー（クライアント）。サーバーはハッシュのみ |
| 管理者 | 他ユーザーのトークンを一覧（値は非表示）で確認し失効できる。操作は監査ログ |
| アプリ名 | Clipshare Quick |
| 言語 | 日本語のみ |
| 実装言語 | Rust（クライアント） |
| 右クリック | Windows 11 最上位メニュー、画像・動画、署名付きMSIXのシェル拡張（IExplorerCommand） |
| SteamVR | HUDトースト＋ダッシュボードパネル（自動アップロードON/OFF、直近写真の削除）。**QR・手首オーバーレイ・OSC は対象外** |
| インストーラー | MSIX（インストール先はWindows管理、UIで変更不可） |
| 署名 | まず自己署名。公開時に最終決定（要ユーザー判断） |
| 更新 | GitHub Releases（公開リポジトリ）。通知してユーザーが選んで適用。VRChat中に勝手に再起動しない。MSIXの事前検証はせず、右クリック拡張を更新できなければ再起動を求める |
| ダウンロードページ | Clipshare の `/qick/download` |
| ソース公開 | 公開、MIT |
| 開発環境 | Clipshare側はサーバーで検証、クライアントはWindows |
| 本番反映 | ブランチ運用とDBマイグレーション手順を指示書に含める |

## 3. Clipshare側の改修（要約。詳細は INSTRUCTIONS）
- 追加: `POST /api/v1/quick`、`DELETE /api/v1/quick/{id}`、認可・トークンAPI、`ApiToken` モデル（端末ごと、ハッシュ保存、失効可）、AccountLevel にツール用上限列、バナー分岐、画質選択、トークン別レート制限、動画マジックバイト検証、OGP、管理画面（上限・トークン管理）、`/qick/download`。
- 現状（確認済み）: Next.js App Router / Prisma(MySQL) / NextAuth / sharp / nanoid。`QuickShare`（publicId=nanoid(10), deleteToken, kind IMAGE/VIDEO, status PROCESSING/READY/FAILED, expiresAt, userId, ipHash）。現行 `POST /api/qick/upload` はセッションCookie認証のみ。閲覧 `/q/{id}/view` にOGP無し。現行既定: 画像20MB/動画200MB/24h/匿名5件。画像処理は回転補正→長辺2000px→バナー合成→WebP q88。Discordボット用ルートに Bearer シークレット方式あり。

## 4. クライアント仕様（要約。詳細は INSTRUCTIONS）
トレイ常駐。写真フォルダ監視→自動アップロード→URLコピー→トースト→履歴。書き込み途中ファイルを拾わない、重複送信しない。設定: 自動アップロードON/OFF、撮影後にURLコピー、既定画質、写真フォルダ、Windows起動時に起動。右クリック共有（進捗ウィンドウ）。Windows通知トースト。SteamVR HUD/パネル。インストーラー/更新/アンインストール。

## 6. 未検証（実装中に検証して報告）
VRChat `config.json` の出力先読み取り（不可なら既定 `Pictures\VRChat`＋手動）、sharp のメタデータ除去、DiscordとXでの OGP 表示、NextAuth への認可フロー組み込み、ライトテーマのコントラスト、MSIX更新（右クリック拡張がExplorerに保持されている場合の更新）、GitHub Releases での `.appinstaller`。

## 7. 共通開発ルール（ユーザー標準）
DBで管理できる設定はDB、`.env` は最小限／WebUIから変更可／APIとUIを分離／型注釈を徹底／エラー処理・例外処理・詳細ログ／セキュリティ重視／保守性・可読性・拡張性最優先／不明点は実装せず質問／完成後に複数回セルフレビュー／指示にはチェック項目・レビュー項目・テスト内容を含める。品質優先で時間がかかっても妥協しない。
